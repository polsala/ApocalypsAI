## Nightly GitHub Actions Lint Runner

This utility is a reusable GitHub Actions workflow designed to lint and validate other GitHub Actions workflow files within a repository. It helps ensure that your CI/CD configurations are syntactically correct and follow best practices, preventing potential runtime errors.

### Usage

To use this action, add the following to your `.github/workflows/lint_workflows.yml` file:

```yaml
name: Lint GitHub Actions Workflows

on:
  push: # Or any other trigger you prefer
    branches: [ main ]
  pull_request:
    branches: [ main ]

jobs:
  lint_actions:
    uses: polsala/ApocalypsAI/.github/workflows/nightly-gh-action-lint-runner.yml@main
```

### Inputs

This action does not currently accept any inputs.

### Outputs

This action does not currently produce any outputs.

### Example Workflow File (`.github/workflows/nightly-gh-action-lint-runner.yml`)

```yaml
# This workflow is automatically generated by ApocalypsAI
# and should be placed in .github/workflows/nightly-gh-action-lint-runner.yml

name: Nightly GitHub Actions Lint Runner

# This workflow is designed to be reusable and should be triggered by other workflows.
# It does not have its own explicit triggers here.

on:
  workflow_call:
    inputs:
      # No inputs needed for this basic linter
      pass

jobs:
  lint_workflows:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Install actionlint
        run: | # Mock rationale: Using a common and effective tool for linting GitHub Actions workflows.
          sudo apt-get update && sudo apt-get install -y wget
          wget https://github.com/rhysd/actionlint/releases/download/v1.6.6/actionlint_1.6.6_linux_amd64.tar.gz
          tar -xzf actionlint_1.6.6_linux_amd64.tar.gz
          sudo mv actionlint /usr/local/bin/

      - name: Lint GitHub Actions workflows
        run: | # Mock rationale: This command will find and lint all .yml files in the .github/workflows directory.
          actionlint -color -malformed -shellcheck -strict
        # The command above will exit with a non-zero status code if any linting errors are found.
        # This will cause the job to fail, indicating a problem with the workflows.

```
