# Nightly PR Labeler\n\nA tiny GitHub Action that automatically adds helpful labels to a pull request based on the files that were changed.\n\n## Features\n\n- Detects documentation changes (files in `docs/` or Markdown files) → adds `documentation` label\n- Detects test changes (files in `tests/` or typical test file suffixes) → adds `tests` label\n- Detects CI/CD changes (files in `.github/` or any YAML file) → adds `ci` label\n- Detects source code changes (common code extensions) → adds `code` label\n- Works with any repository that provides a `repo-token` with `pull_requests` scope.\n\n## Usage\n\nCreate a workflow file (e.g., `.github/workflows/pr-labeler.yml`) and add the following step to your PR workflow:\n\n```yaml\nname: PR Labeler\n\non:\n  pull_request:\n    types: [opened, synchronize, reopened]\n\njobs:\n  label:\n    runs-on: ubuntu-latest\n    steps:\n      - uses: actions/checkout@v3\n      - name: Auto‑label PR\n        uses: ./nightly-pr-labeler\n        with:\n          repo-token: ${{ secrets.GITHUB_TOKEN }}\n```\n\nThe action will run on every PR event, inspect the changed files and apply the appropriate labels.\n\n## Inputs\n\n| Name | Description | Required | Default |\n|------|-------------|----------|---------|\n| `repo-token` | GitHub token with permission to read PR files and add labels. Usually `{{ secrets.GITHUB_TOKEN }}`. | Yes | – |\n\n## Development\n\nThe action is implemented in JavaScript and uses the official `@actions/*` packages. To run the tests locally:\n\n```bash\nnpm install\nnpm test\n```\n\n## License\n\nMIT
