# Nightly PR Labeler\n\nA tiny GitHub Action that automatically adds labels to a pull request based on keywords found in its title.\n\n## Why?\n\nKeeping PRs consistently labeled helps triage, reporting, and automation. This action looks for common words like `bug`, `feature`, `docs`, etc., and emits a `labels` output that can be fed to the `actions/labeler` action or used in a subsequent step.\n\n## Usage\n\n```yaml\nname: PR Auto‑Label\n\non:\n  pull_request:\n    types: [opened, edited]\n\njobs:\n  label:\n    runs-on: ubuntu-latest\n    steps:\n      - name: Checkout\n        uses: actions/checkout@v3\n\n      - name: Determine labels\n        id: labeler\n        uses: ./\.github/actions/nightly-pr-labeler\n        with:\n          title: ${{ github.event.pull_request.title }}\n\n      - name: Apply labels\n        uses: actions/labeler@v4\n        with:\n          repo-token: ${{ secrets.GITHUB_TOKEN }}\n          labels: ${{ steps.labeler.outputs.labels }}\n```\n\n## Inputs\n\n| Name | Description | Required |\n|------|-------------|----------|\n| `title` | The pull‑request title to analyse. Usually `github.event.pull_request.title`. | Yes |\n\n## Outputs\n\n| Name | Description |\n|------|-------------|\n| `labels` | Comma‑separated list of labels that matched the title. Empty string if none matched. |\n\n## Supported Keywords\n\n| Keyword | Produced label |\n|---------|----------------|\n| `bug`, `fix` | `bug` |\n| `feature`, `feat` | `enhancement` |\n| `docs` | `documentation` |\n| `test` | `tests` |\n| `refactor` | `refactor` |\n| `chore` | `chore` |\n\nThe mapping is case‑insensitive and matches if the keyword appears anywhere in the title.\n\n## License\n\nMIT – see LICENSE file in the repository.\n
