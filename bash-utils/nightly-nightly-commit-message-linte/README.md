# Nightly Commit Message Linter\n\n## Overview\nA tiny Bash utility that checks a Git commit message file for compliance with the Conventional Commits format. It validates the subject line length, required type prefix, and body line length.\n\n## Usage\n```bash\n./commit-lint.sh <path-to-commit-message-file>\n```\n\nThe script exits with code **0** if the message passes all checks, otherwise it prints an error and exits with **1**.\n\n## Checks performed\n1. **Subject line length** – must be ≤ 50 characters.\n2. **Conventional Commits format** – subject must start with one of `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore` (optionally followed by a scope in parentheses) and a colon, e.g. `feat(parser): add support`.\n3. **Body line length** – each non‑empty body line must be ≤ 72 characters.\n\n## Example\n```bash\ncat >msg.txt <<'EOF'\nfeat(parser): add new parsing logic\n\nImplemented support for nested structures.\nAll tests pass.\nEOF\n\n./commit-lint.sh msg.txt\n```\n\nIf the message is valid you will see:\n```
Commit message looks good.\n```\n\nOtherwise an error is printed and the script exits with status 1.\n\n## Testing\nRun the bundled test suite with:\n```bash\ncd tests && ./test_commit_lint.sh\n```\n
