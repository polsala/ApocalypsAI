# Nightly Safehouse S3\n\n## Overview\n\nA whimsical yet practical Terraform module that provisions a secure Amazon S3 bucket suitable for storing post‑apocalyptic safe‑house data. The bucket includes:\n\n- **Versioning** – keep historical copies of objects\n- **Server‑side encryption (AES‑256)** – data at rest is encrypted\n- **Lifecycle rule** – automatically delete objects older than 30 days\n- **Read‑only IAM policy** – grants a specified IAM role read‑only access to the bucket\n\n## Usage\n\n```hcl\nmodule "safehouse" {\n  source            = "./nightly-safehouse-s3"\n  bucket_name       = "my-safehouse-bucket"\n  allowed_role_name = "my-readonly-role"\n}\n\noutput "bucket_id" {\n  value = module.safehouse.bucket_id\n}\n\noutput "policy_arn" {\n  value = module.safehouse.policy_arn\n}\n```\n\n## Variables\n\n| Name | Description | Type | Required |\n|------|-------------|------|----------|\n| `bucket_name` | Name of the S3 bucket to create. Must be globally unique. | `string` | yes |\n| `allowed_role_name` | IAM role name that will receive read‑only access to the bucket. | `string` | yes |\n\n## Outputs\n\n| Name | Description |\n|------|-------------|\n| `bucket_id` | The ID of the created S3 bucket. |\n| `policy_arn` | ARN of the generated read‑only IAM policy. |\n\n## Testing\n\nA simple Bash test script is provided under `tests/`. It runs `terraform init`, `terraform validate`, and a dry‑run `terraform plan` with mock variable values. No AWS credentials are required because the test uses the local backend and does not apply any resources.\n\n```bash\ncd nightly-safehouse-s3\n./tests/test_safehouse.sh\n```\n\n## License\n\nMIT – feel free to adapt and reuse in your own post‑apocalyptic infrastructure projects.
