# Nightly Safehouse S3 Bucket\n\n## Overview\n\nThis Terraform module creates an Amazon S3 bucket configured as a "safe‑house" for your critical data. Features include:\n\n- **Versioning** – keep every version of an object.\n- **Server‑side encryption (SSE‑S3)** – data at rest is encrypted automatically.\n- **Lifecycle rule** – objects older than 30 days are automatically deleted, freeing space.\n- **Optional secret** – a randomly generated password stored in AWS Secrets Manager for any ancillary service you might need.\n\nThe module is deliberately whimsical but fully functional, suitable for demos, training, or a real‑world backup vault.\n\n## Usage\n\n```hcl\nmodule \"safehouse\" {\n  source        = "./utils/nightly-safehouse-s3-bucket"\n  bucket_name   = "my‑post‑apoc‑vault"\n  enable_secret = true\n}\n```\n\n## Variables\n\n| Name | Type | Description | Default |\n|------|------|-------------|---------|\n| `bucket_name` | `string` | Name of the S3 bucket (must be globally unique). | n/a |\n| `enable_secret` | `bool` | Whether to create a random password in Secrets Manager. | `true` |\n\n## Outputs\n\n| Name | Description |\n|------|-------------|\n| `bucket_arn` | ARN of the created S3 bucket. |\n| `secret_arn` | ARN of the Secrets Manager secret (empty string if `enable_secret` is false). |\n\n## Testing\n\nThe module includes a simple validation script that runs `terraform init` (with a local backend) and `terraform validate`. See `tests/validate.sh`.\n\n## Notes\n\n- The module uses the **AWS provider**; ensure you have valid credentials configured when applying.\n- No real AWS resources are created during CI testing because the test script runs with `-backend=false` and does not execute `terraform apply`.\n- The random password is generated using the `random_password` resource, which does not require any external API calls.\n
