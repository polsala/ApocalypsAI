# Nightly Apocalypse Safeguard Terraform Module\n\nA whimsical yet practical Terraform module that creates a versioned, encrypted S3 bucket with lifecycle rules suitable for storing precious post‑apocalyptic data.\n\n## Features\n\n- **Versioning** – keep every version of an object.\n- **Server‑Side Encryption** – AES‑256 encryption at rest.\n- **Lifecycle** – transition objects to Glacier after 30 days, delete after 365 days.\n- **Random suffix** – avoids naming collisions.\n\n## Usage\n\n```hcl\nmodule "apocalypse_safeguard" {\n  source               = "git::https://github.com/your-org/apocalypsai.git//terraform-modules/nightly-apocalypse-safeguard"\n  bucket_name_prefix   = "my‑apocalypse‑data"\n  region               = "us-east-1"\n}\n```\n\n## Inputs\n\n| Name | Description | Type | Default | Required |\n|------|-------------|------|---------|----------|\n| bucket_name_prefix | Prefix for the bucket name; a random suffix will be added. | string | n/a | yes |\n| region | AWS region for the bucket. | string | n/a | yes |\n\n## Outputs\n\n| Name | Description |\n|------|-------------|\n| bucket_name | The full bucket name. |\n| bucket_arn  | The ARN of the bucket. |\n\n## Testing\n\nRun the provided test script:\n\n```sh\ncd terraform-modules/nightly-apocalypse-safeguard\n./tests/validate.sh\n```\n\nThe script runs `terraform init` (backend disabled) and `terraform validate`. It should exit with status 0.\n\n## License\n\nMIT
