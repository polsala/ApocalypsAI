# Nightly Terraform S3 Website\n\n## Overview\n\nA tiny, whimsical Terraform module that creates an Amazon S3 bucket set up for static website hosting. It lets you specify the bucket name and optional index/error documents. Perfect for quickly standing up a static site in a post‑apocalyptic cloud.\n\n## Usage\n\n```hcl\nmodule "static_website" {\n  source          = "./"\n  bucket_name     = "my‑awesome‑site"\n  index_document  = "index.html"   # optional, defaults to index.html\n  error_document  = "error.html"   # optional, defaults to error.html\n}\n\noutput "website_url" {\n  value = module.static_website.website_endpoint\n}\n```\n\n## Variables\n\n| Name | Type | Description | Default |\n|------|------|-------------|---------|\n| `bucket_name` | `string` | Name of the S3 bucket (must be globally unique) | n/a |\n| `index_document` | `string` | Index document for the website | `"index.html"` |\n| `error_document` | `string` | Error document for the website | `"error.html"` |\n\n## Outputs\n\n| Name | Description |\n|------|-------------|\n| `bucket_id` | The ID of the created S3 bucket |\n| `website_endpoint` | The website endpoint URL (e.g., `http://my‑awesome‑site.s3-website-us-east-1.amazonaws.com`) |\n\n## Testing\n\nA simple offline test is provided under `tests/`. It merely checks that the module defines the expected `aws_s3_bucket` resource. Run it with:\n\n```bash\ncd tests && ./test_main.sh\n```\n\n## License\n\nMIT – because even in the wasteland we share our code.\n
