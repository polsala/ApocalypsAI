# nightly-apocalypse-safehouse-s3

A whimsical yet practical Terraform module that creates a secure S3 bucket for storing your post‑apocalyptic safe‑house data. The bucket has versioning enabled, a configurable lifecycle rule to expire old objects, optional server‑side logging, and a randomly generated access password (stored as a Terraform output) that you can use for client‑side encryption.

## Features

- **Versioning** – never lose a previous version of your critical files.
- **Lifecycle expiration** – automatically delete objects older than a configurable number of days.
- **Optional access logging** – send S3 access logs to a separate bucket.
- **Random password** – a 16‑character alphanumeric password generated by the `random_password` resource.

## Usage

```hcl
module "safehouse" {
  source          = "./nightly-apocalypse-safehouse-s3"
  bucket_name     = "my‑post‑apoc‑safehouse"
  expiration_days = 730   # keep objects for 2 years
  enable_logging  = true
}

output "access_password" {
  value = module.safehouse.access_password
}
```

## Variables

| Name | Type | Description | Default |
|------|------|-------------|---------|
| `bucket_name` | `string` | Name of the S3 bucket (must be globally unique). | n/a |
| `expiration_days` | `number` | Number of days after which objects are expired. | `365` |
| `enable_logging` | `bool` | Whether to enable S3 server‑side access logging (requires a separate logging bucket). | `false` |

## Outputs

| Name | Description |
|------|-------------|
| `bucket_id` | The ID of the created bucket. |
| `bucket_arn` | The ARN of the created bucket. |
| `access_password` | Randomly generated password for client‑side encryption. |

## Testing

The module includes a deterministic offline test script (`tests/test_module.sh`) that runs `terraform init` and `terraform validate` using a local backend. No real AWS credentials are required.

```bash
cd tests && ./test_module.sh
```
