# Nightly Portal Traffic Simulator\n\n## Overview\n\n`nightly-portal-traffic-simulator` is a whimsical yet practical Go utility that starts a tiny HTTP server mimicking a post‑apocalyptic communication hub.  It provides two endpoints:\n\n- `GET /ping` – returns a simple *pong* string (great for health‑checks).\n- `GET /survivor` – returns a JSON payload describing a randomly generated survivor (name, health, supplies).\n\nIn addition, the server can generate its own background traffic to stress‑test log parsers or monitoring pipelines.  The code is deliberately lightweight, uses only the Go standard library, and showcases Go's concurrency primitives (goroutines, channels, and the net/http package).\n\n## Build\n\n```bash\n# Clone the repository (or copy the utility folder)\ncd utils/nightly-portal-traffic-simulator\n# Build the binary\ngo build -o portal-sim src/main.go\n```\n\n## Run\n\n```bash\n# Run with default settings (listens on :8080)\n./portal-sim\n```\n\nThe server will start printing log lines like `Portal Traffic Simulator listening on :8080`.  By default it also spawns a background goroutine that continuously sends random requests to itself every 500 ms.  To disable this auto‑traffic, set the environment variable `DISABLE_AUTO=1` before starting the binary.\n\nYou can also change the listening port via the `PORT` environment variable:\n\n```bash\nPORT=9090 ./portal-sim\n```\n\n## Endpoints\n\n- **`GET /ping`** – response body: `pong` (plain text).\n- **`GET /survivor`** – response body: JSON, e.g.\n  ```json\n  {\n    "name": "Ava",\n    "health": 73,\n    "supplies": 12\n  }\n  ```\n\n## Testing\n\nThe utility ships with a Go test suite that validates both endpoints.  Run the tests with:\n\n```bash\ngo test ./tests\n```\n\nAll tests are deterministic and do not require network access beyond the in‑process test server.\n\n## License\n\nMIT – see the top‑level LICENSE file.\n
