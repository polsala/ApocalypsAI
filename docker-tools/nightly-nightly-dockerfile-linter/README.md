# nightly-dockerfile-linter\n\nA whimsical yet useful Docker‑file linter packaged as a self‑contained Docker image.\n\n## What it does\n\n* Detects usage of the `latest` tag in `FROM` statements.\n* Flags the deprecated `MAINTAINER` instruction.\n* Suggests using `COPY` instead of `ADD`.\n* Warns when a `EXPOSE` port is set to `0` (meaningless).\n\nIf no issues are found it prints a happy ✅ message.\n\n## Building the image\n\n```bash\ndocker build -t nightly-dockerfile-linter -f src/Dockerfile src\n```\n\n## Running the linter\n\nPass the path to the Dockerfile you want to check (inside the container) as the sole argument.\n\n```bash\n# Example – lint a local Dockerfile\n# Mount the file into the container at /Dockerfile\n\ndocker run --rm -v $(pwd)/Dockerfile:/Dockerfile nightly-dockerfile-linter /Dockerfile\n```\n\n## Example output\n\n```\n⚠️ Avoid using the `latest` tag in FROM statements.\n⚠️ Prefer COPY over ADD for copying files.\n⚠️ MAINTAINER instruction is deprecated; use a LABEL instead.\n✅ Dockerfile looks good!\n```\n\n## Testing\n\nThe repository includes a Bash test that builds the image, runs it against a deliberately broken Dockerfile and asserts that the expected warnings appear. Run it with:\n\n```bash\ncd tests && ./test_linter.sh\n```\n
